# STAGE DECLARATIONS ADDED WITH THE SLUG CONVERSION
#
# Every file in this mod now carries the mod's slug in its name and its path,
# and every manifest entry declares `source: self`. That is what stops two
# mods claiming one relative path - and it also means the loose-file walk no
# longer hands this mod's geometry to a stage row the mod never declared. A
# row this mod was dressing by path alone draws vanilla from here on unless
# it is declared below: modConfigParseStage writing g_ModStageNums[stagenum]
# is the only thing that makes this mod's level data and textures reachable
# (port/src/mod.c:2436).
#
# One block per row whose whole vanilla file set is the level this mod ships
# - bg, tiles, pads and setup all name the same level, so bg_mp8.seg is
# STAGE_TEST_MP8's own geometry and STAGE_TEST_MP8 is declared. Rows that
# merely reuse that geometry are NOT declared here; nor is a row two mods
# both ship the primary geometry for. Both sets are listed, with counts, in
# stage-extra-rows.md at the umbrella root.
#
# Only keys this mod actually ships are named. A key left out keeps the stage
# row's vanilla file, which is what it resolved to before.
#
# Twenty of these rows now carry `kind mp` and an `arenaname` - see the
# COMBAT SIMULATOR REGISTRATION block immediately below, which is where the
# names came from and what the list becomes. STAGE_TEST_RUN is deliberately
# not one of them; it ships no mpsetupfile.
# --------------------------------------------------------------------------


# --------------------------------------------------------------------------
# COMBAT SIMULATOR REGISTRATION
#
# catherine: "now I'd like to register these mp arenas in the combat
# simulator. the friendly strings can just be best guess (slug or nickname if
# we have it)".
#
# TEN OF THE TWENTY ARE RENAMES, NOT NEW ROWS. mpArenasRebuild
# (src/game/mplayer/setup.c:256-261) looks each registered stagenum up in
# g_MpArenas_Vanilla first; a hit writes `arenaname` into that row's
# customname and appends nothing, because appending would list the stage
# twice. Ten of these rows ARE vanilla Combat Simulator arenas whose geometry
# this mod replaces, so the vanilla names go away and the GoldenEye X names
# take their place:
#
#   STAGE_MP_SKEDAR     "Skedar"    -> "Temple"
#   STAGE_MP_PIPES      "Pipes"     -> "Aztec"
#   STAGE_MP_SEWERS     "Sewers"    -> "Basement"
#   STAGE_MP_WAREHOUSE  "Warehouse" -> "Library"
#   STAGE_MP_RUINS      "Ruins"     -> "Caverns"
#   STAGE_MP_AREA52     "Area 52"   -> "Caves"
#   STAGE_MP_FORTRESS   "Fortress"  -> "Stack"
#   STAGE_MP_CARPARK    "Car Park"  -> "Facility"
#   STAGE_MP_TEMPLE     "Temple"    -> "Archives"
#   STAGE_MP_FELICITY   "Felicity"  -> "Egyptian"
#
# That is not a naming choice. On those ten rows bgfile/tilesfile/padsfile/
# mpsetupfile all point at this mod's level, so the vanilla arena is not
# reachable any more whatever the row is called. Six vanilla arenas are left
# untouched: Ravine, G5 Building, Grid, Base, Villa, Complex.
#
# The other ten APPEND. Combined with the four blocks at the top of this file
# that already had `kind mp`, this mod contributes 14 appended rows.
#
# WHERE THE NAMES CAME FROM. This mod ships no L* lang file of its own, so the
# pack's names live in mod_aio_stages' LmpmenuE_aio (1173, 5-byte header, raw
# deflate; 496 slots) - 48 of those slots are rewritten against
# src/assets/ntsc-final/lang/mpmenu.json, and the rewritten block at
# L_MPMENU_296..338 is the GoldenEye X / Zelda / Dark Noon / Goldfinger arena
# names. Which name goes with which stagenum is not guessable from that block
# alone, so it was read out of the pack's own shipped binary,
# PD_AIO_March_2026/pd.exe:
#
#   - its arena table at file offset 0x215440 - 75 rows of
#     {s16 stagenum, u8 requirefeature, u16 langid}, ending on the Random row
#     (stagenum 1, L_MPMENU_136), with the vanilla 16 at the front in vanilla
#     order. The four blocks at the top of this file are rows 39, 43, 45 and
#     48 of it and agree exactly: 0x10 Bunker, 0x49 Facility BZ, 0x07 Train,
#     0x14 Archives 1F.
#   - its stage table at file offset 0x217ec0 - 88 rows of
#     sizeof(stagetableentry)==60, giving stagenum -> bg/tiles/pads/mpsetup
#     file ids. The pack extended that table for GoldenEye X, so a GEX level
#     usually sits on a STAGE_EXTRA* stagenum whose bg file id is the same one
#     the vanilla row uses. That file id is the join: bg_oat is this mod's
#     bg_oat_gex.seg, the pack's stagenum 0x0b also reads bg_oat, and the
#     pack calls 0x0b "Temple" - so bg_oat_gex.seg is GoldenEye X's Temple,
#     whatever row it is declared on here.
#
# The 22 names this resolves to are exactly the 22 in the "# Playable:" list
# carried over from the source modconfig above, which is the cross-check.
#
# FOUR ARE SLUG PLACEHOLDERS, PENDING A HUMAN PASS. The pack lists no arena at
# all for bg_cat, bg_len and bg_old - no row of its arena table reaches
# stagenum 0x28, 0x36 or 0x4e - and its bg_mp7 row (0x3f) is named "Valley",
# which README.txt credits to Dark Noon; mod_dark_noon ships its own,
# different bg_mp7.seg (different md5), so "Valley" is not this mod's level.
# Those four get a lowercase slug with a `_gex` marker - cat_gex, len_gex,
# old_gex, mp7_gex - the same convention the aio pass settled on. A slug reads
# as provisional in the menu, which is the point. They are named after the
# geometry file rather than after the vanilla level of that row on purpose:
# the vanilla level is NOT what is in there.
#
# DO NOT DELETE AN `arenaname` TO TIDY IT AWAY. A `kind mp` row with no
# arenaname draws NULL, not a fallback name. modConfigParseStage records the
# stage with the langid argument HARD-CODED 0 (port/src/mod.c:2615) and no
# modconfig key sets it; mpArenasRebuild copies that into the appended
# mparena, and the menu does `if (customname) return customname; return
# langGet(name)` (src/game/mplayer/setup.c:532-535). langGet(0) is bank 0
# index 0, g_LangFiles[0] is 0 (src/game/lang.c:75), so bank 0 is never loaded
# and it returns NULL. The string is the only thing keeping that path from
# being taken. Rename them; do not remove them.
#
# THE MEMORY BUDGET, PER ROW. g_StageAllocations8Mb (src/lib/main.c:90) is
# keyed by stagenum. Checked all twenty: nineteen have their own row, which is
# the difference from the aio pass - these are real arena rows, not
# STAGE_EXTRA* ones. Two to watch:
#
#   STAGE_EXTRA16 has NO row. It falls off the end onto the terminator,
#   `-ml0 -me0 -mgfx120 -mvtx98 -ma300`, the smallest budget in the table, and
#   an `allocation` key cannot fix it - mod.c:2534 refuses it for a stage with
#   no row there and says so in the log.
#
#   STAGE_TEST_LEN has a row, but it is `-ml0 -me0 -mgfx120 -mvtx98 -ma300` -
#   the same smallest budget. Its setup is the largest of the twenty at 19
#   spawns.
#
#   The other eighteen are `-mgfx200 -mvtx200 -ma400` (the vanilla arena
#   budget) except STAGE_28 and STAGE_TEST_OLD, which are
#   `-ml0 -me0 -mgfx120 -mvtx98 -ma400`.
#
# IF ONE OF THESE FALLS OVER, LOOK THERE FIRST. Never played: there is no
# cmake and no SDL2 in this workspace, so nothing below was built or run.
#
# STAGENUMS. All twenty are <= 0x7f, the highest being STAGE_EXTRA16 at 0x51.
# g_MpSetup.stagenum is persisted in 7 bits (mplayer.c:4692 write, :4615 read)
# with no clamp on the way back, so a stagenum over 127 would come back
# truncated. None of these can hit that.
#
# Every block names the stage by its STAGE_* spelling, never a bare number.
# `stage <n>` numerically is a STAGENUM, not a g_Stages row index, and the
# name form resolves through stageGetIndexByName (mod.c:2411) and cannot be
# read the wrong way.
#
# Spawn counts below are read out of each Ump_setup*_gexZ by walking the intro
# list the way src/game/mplayer/scenarios.c:851 does. The method was checked
# against mod_aio_stages' Ump_setuparch_aioZ, which the Suburb block there
# records as "12 spawns, 4 case points, 6 hills"; the walk reads exactly that.
# No block below has an empty setup - the lowest is 12 spawns.
# --------------------------------------------------------------------------

# --------------------------------------------------------------------------
# MODEL SCALES
#
# Ported from jonaeru's GoldenEye X build (github.com/jonaeru/perfect_dark,
# branch allinone-latest). That tree carries a second full copy of
# g_ModelStates called g_GexModelStates, 443 rows, at
# src/game/modeldata/general.c:854, under `#ifndef PLATFORM_N64`. Diffed
# against the vanilla table in the same file it is 19 rows different, every
# one of them `scale 0x1000 -> 0x0199`, and not one `file` field differs.
# Those 19 rows are what this block reproduces. The work is jonaeru's; only
# the mechanism is ours.
#
# WHY IT IS NEEDED AT ALL. objInitWithModelDef gives every prop
# g_ModelStates[modelnum].scale * (1/4096) (src/game/propobj.c:2129) and that
# is the only scale the renderer has for it. A stage mod that replaces a
# vanilla prop MODEL does not replace the vanilla row of that table, so it
# inherits a scale chosen for a model it is not shipping. Measured over the
# files in this basedir, 78 of 128 replaced prop models differ from the
# vanilla model they replace by more than 50% of its size.
#
# WHY WE DO NOT NEED A SECOND TABLE. modConfigParseModelStates
# (port/src/mod.c:1175) already writes g_ModelStates[n].scale per mod,
# modCacheAllConfigs caches the result per mod, and modSwitch memcpys the
# right one in (port/src/mod.c:3516). No shipped modconfig had ever declared
# a ModelStates block, so this is the first exercise of it.
#
# THE LITERAL IS NOT 0.1, AND THE NEAR MISSES ARE SILENT.
# modConfigParseModelStates stores (u16)(scale * 4096.0f) - a truncation
# toward zero, not a round (port/src/mod.c:1222). Measured with strtof and
# the same cast:
#   0.09985            -> 408.9856  -> 408  = 0x0198   WRONG, and silent
#   0.099853515625     -> 409.0     -> 409  = 0x0199   what we want
#   0.1                -> 409.6001  -> 409  = 0x0199   right answer, by luck
# 0.099853515625 is exactly 409/4096. It is a dyadic rational with a 9-bit
# significand, so strtof returns it exactly, multiplying it by 4096.0f is an
# exact power-of-two scaling, and the cast has nothing to round away. It is
# the only literal in that list that is true rather than lucky.
#
# ALL 19 ARE MODELS THIS MOD SHIPS A REPLACEMENT FOR. Checked against
# mod_gex_stages_filetable.json: every one of the 19 has a `replaces` entry
# here (Pa51_crate1Z -> Pa51_crate1_gexZ, and so on). Nothing was dropped,
# and nothing was added. Declaring a scale for a model this mod does NOT
# replace would shrink a *vanilla* prop in these stages by 10x, which is a
# new bug rather than a fix.
#
# 0x0199 IS NOT AN ODD NUMBER FOR THIS TABLE. 152 rows of vanilla
# g_ModelStates already carry 0x0199; 281 carry 0x1000. The port moves these
# 19 from the one common value to the other.
#
# A BAD VALUE HERE COSTS EVERYTHING AFTER IT. modConfigParseModelStates
# returns NULL on a malformed model id, a missing brace or a scale <= 0;
# modConfigLoad then sets success = false and breaks out of its parse loop
# (port/src/mod.c:3015-3025). There is no rollback, so what has already been
# applied stays applied and everything further down the file is abandoned.
# That is why this block sits LAST: a typo here cannot cost the 25 stage
# declarations above it. Keep it last, and do not hand-edit a value without
# re-reading that path.
#
# RE-PARSING IS SAFE. `Scale` assigns, it does not accumulate, and
# modConfigLoad memcpys g_ModelStatesOriginal back over g_ModelStates before
# every parse (port/src/mod.c:2906). The block is skipped outright while
# g_MainIsBooting is set, so the boot-time passes do nothing; the pass that
# takes is modCacheAllConfigs, which mainProc calls after mainInit has
# cleared the flag (port/src/pdmain.c:344, :353).
#
# Comment is `#` to end of line, `{` and `}` are their own tokens, the model
# id goes through strtol(base 0) so 0x… is read as hex, and `Scale` is
# matched case-insensitively. Do not put a comma in here: `,` is a token
# separator (port/src/utils.c:12).
# --------------------------------------------------------------------------
